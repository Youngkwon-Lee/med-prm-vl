1. MV (Majority Voting)란?

1.1 정의

MV (Majority Voting) = 투표 기반 앙상블
N개의 솔루션이 있을 때, 각 솔루션의 최종 답변을 투표로 비교하여
가장 많이 선택된 답변을 최종 정답으로 선택하는 방식

예시:
64개 솔루션이 생성됨 → 각 솔루션의 최종 답변 추출
답변 A: 40개 (가장 많음) → 선택 ✓
답변 B: 20개
답변 C: 4개

1.2 ORM vs PRM vs MV 비교

방식 설명 선택 기준 장단점
ORM
(Outcome Reward
Model)		 최종 답변의 정확도만 평가
(프로세스 무시)		 최고 ORM 점수 솔루션 선택 • 장: 단순, 빠름
• 단: 프로세스 무시, 정보 손실
PRM
(Process Reward
Model)		 각 단계별 정확도 평가
(프로세스 중심)		 최소 PRM 점수가 높은 솔루션 선택
(BoN: Best-of-N)		 • 장: 프로세스 평가, 정밀함
• 단: 복잡, 느림
MV
(Majority Voting)		 모든 솔루션의 최종 답변으로 투표 가장 많이 선택된 답변 선택
(PRM 점수 무시)		 • 장: 다수결 효과, 편향 감소
• 단: 복잡도 무시

1.3 MV-ORM vs MV-PRM

우리 실행 결과에서의 MV 해석
MV-ORM (2,780/3,950 = 70.4%):
ORM 모델로 생성한 64개 솔루션 → 투표 기반 선택
(ORM 점수는 무시하고 순수 투표만 사용)

MV-PRM (2,765/3,850 = 71.8%):
PRM 모델로 생성한 64개 솔루션 → 투표 기반 선택
(PRM 점수는 무시하고 순수 투표만 사용)

의미:
MV > PRM이면 → 투표가 단순 PRM 선택보다 효과적 (앙상블 효과)
우리 결과: MV-ORM (70.4%) > ORM-BoN (69.6%), MV-PRM (71.8%) > PRM-BoN (70.6%)
→ 투표가 PRM보다 더 정확함을 의미

5. 실제 구현 과정 상세 분석

5.1 Phase 2: Baseline 구현 (4_scoring_PRM.py)

단계 1: 모델 로드
model = AutoModelForCausalLM.from_pretrained(args.model_save_path)

• 모델: llama-3.1-medprm-reward-v1.0 (HPC 서버에 사전 설치)
• 메모리: V100 16GB (bfloat16 또는 float16 사용)
• Device: CUDA (GPU 자동 할당)
단계 2: ORM vs PRM 선택
--use_orm yes/no # ORM 또는 PRM 모델 선택

• ORM: 최종 답변 평가만 (프롬프트: "If the final answer is correct/incorrect, output +/-")
• PRM: 각 단계별 평가 (프롬프트: "If the reasoning in a step is logical, output +/-")
단계 3: RAG 모드 선택
--use_rag yes/no # RAG 사용 여부

• RAG Yes: related_docs를 포함한 평가 (의료 문서 활용)
• RAG No: 순수 PRM 평가만 (우리 Phase 2에서 사용)

우리가 사용한 설정: --use_rag no (순수 평가 기준선)
단계 4: PRM 점수 계산
def get_prob(text): # 1. 텍스트를 토크나이즈 input_ids = tokenizer(text) # 2. 모델의 출력 logits 얻음 logits = model(input_ids).logits # 3. "+" 와 "-" 토큰의 확률 계산 plus_prob = softmax(logits[position, plus_token_id]) # 4. 각 step별로 반복 (단계별 점수) # step_scores = [0.95, 0.87, 0.72, ...] (각 단계의 "+" 확률)
단계 5: N개 솔루션 평가
각 질문마다 64개 솔루션 평가:

for solution in 64_solutions: # 각 솔루션의 단계별 점수 계산 step_scores = [0.95, 0.87, 0.72, 0.65] # 4개 단계 # PRM 방식: 최소 점수 = 0.65 (가장 약한 단계) # BoN 선택: min_score가 가장 높은 솔루션 선택
단계 6: Majority Voting (MV)
64개 솔루션의 최종 답변 투표:

solutions_answers = ["A", "B", "A", "A", ..., "A"] # 64개 answer_votes = Counter(solutions_answers) # Counter({'A': 40, 'B': 20, 'C': 4}) final_answer = answer_votes.most_common(1)[0] # 'A' (40표)
단계 7: 정확도 계산
prm_correct = 0 # PRM BoN 방식의 정답 개수 mv_correct = 0 # MV 방식의 정답 개수 for item in data: # PRM BoN: 최고 점수 솔루션 선택 best_solution = max(solutions, key=lambda x: x.min_score) if best_solution.answer == correct_answer: prm_correct += 1 # MV: 투표로 선택 mv_answer = majority_vote(solutions) if mv_answer == correct_answer: mv_correct += 1 prm_accuracy = prm_correct / total * 100 mv_accuracy = mv_correct / total * 100

5.2 우리의 구현: 4_scoring_PRM.py 코드 요약

함수/변수 설명

• 결과: ORM 2,751/3,950 = 69.6%

• 최다 투표된 답변 선택
